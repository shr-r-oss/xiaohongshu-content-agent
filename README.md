# 好物研究所 · 小红书内容分析 Agent

默认基于新版“小红书好物分享500模拟数据.csv”的本地网页应用。旧版“小红书好物分享500参考笔记.xlsx”保留，可手动导入。两份原始文件只读，不混合使用，避免相同笔记 ID 冲突。

## 启动

在此目录的 PowerShell 运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\启动.ps1
```

打开 http://127.0.0.1:8765 。启动脚本优先使用当前电脑已安装的 Codex Python 运行时。其他电脑安装 Python 3.11+ 后运行 `python -m pip install -r requirements.txt`，再运行 `python app.py`。关闭服务使用 Ctrl+C。可通过 `PORT` 环境变量修改端口。

## 已实现

- CSV / Excel .xlsx 导入、工作表选择、字段别名及手动映射；UTF-8 / GB18030 CSV、多行正文、中文数量单位解析。
- ID 去重、缺失值和非法数值检查、原始数据预览。
- 全量和筛选范围的可解释表现评分、可调权重、排行、分页、CSV 导出。
- 互动散点图、标签频次、指标中位数、原文详情与评分贡献。
- 本地词典拆解、段落查看、两组特征占比、正例和反例。
- 基于主题和受众的本地模板选题草稿，附参考笔记 ID 和验证建议。
- 可配置真实模型的单篇拆解、对照样本规律解读、选题与标题生成；失败反馈、重试、内存缓存。
- JSON 分析报告导出。

## 数据口径

新版 CSV 为用户提供的 500 条模拟笔记，全部可评分；覆盖创意餐盘 198、杯碗茶具 116、托盘收纳 61、桌面摆件 44、餐桌布艺 42、厨房小物 39 条。没有独立层级标签，不能计算“真实爆款”准确率，也不把前 20% 当作标签。应用标记模拟性质，不能用此数据证明真实平台规律或训练效果。

在 2026-09-10 统计口径下，点赞中位数为 1287.5、收藏中位数为 292、评论中位数为 15；默认高表现组 100 条，阈值约 76.34。排行页新增分位数和逐项移除维度后的组员保留率检查，以观察新数据重叠分布下的评分敏感性，未根据模拟样本反复调权重制造高准确率。

原工作表标签不参与评分。ViralScore v2 默认权重如下，各原始维度在当前完整可评分样本内转换成 0–100 平均秩百分位，再加权：

| 维度 | 原始值定义 | 权重 |
| --- | --- | --- |
| Popularity | 点赞数，作为热度代理，不代表曝光量 | 25% |
| EngagementRate | (点赞+收藏+评论) / 粉丝数 | 25% |
| FavoriteValue | 收藏 / (点赞+1)，平滑零点赞分母 | 25% |
| Velocity | (点赞+收藏+评论) / (发布后自然天数+1) | 15% |
| Comment | 评论数 | 10% |

这些维度定义是本版实现口径，非平台官方定义。百分位采用并列平均秩；所有同值时为 50。只有一条可评分记录时不评分。没有映射的维度移除并归一化其余权重，页面显示实际权重；映射了但个别记录缺失必需值时该记录不评分。粉丝数为 0 时互动比不可用。收藏价值和粉丝互动比可以大于 1，原始值不截断。

统计日默认北京时间当天，可改为数据采集日。未来发布日期或无法解析的日期使 Velocity 不可用。前 20% 暂定义为高表现组，可调整并包含同分记录；得分不是未来爆款概率。

规律页同时提供本地词典统计与 LLM 逐篇语义标注，两者分开展示。原有 AI 对照摘要最多发送 6 条高表现与 6 条其余组笔记；新增语义分析可分批覆盖选定范围，并计算 Lift 与正负关联，详见下文。

## Content Generator Agent

在“选题工作台”输入“手作餐盘”，点击“分析规律并生成方案”：

1. 自动将主题匹配到“创意餐盘”；也可手动选择类别。支持六个类别，并把新数据“托盘收纳”映射到“托盘与收纳”。明确类别标签优先，未标类别时用标题别名匹配；未知主题使用标题/标签精确关键词，不做无关样本回退。
2. 沿用当前排行的筛选范围、统计日、ViralScore 权重和高表现标记，提取同类高表现与同类其余笔记。
3. 统计标题 Hook、正文结构特征、标签、使用场景；展示两组命中数和原文引用，不将词典命中当作完整语义或因果结论。
4. 先展示类别数量、标题/产品名词组相似数量、其中高表现数量、实际采用的最多 6 篇证据及匹配原因。按主题相似程度优先，再比较分数，并减少同作者和高度重复的正文。规律仍使用整个同类别组，不把 6 篇参考当作全量统计。
5. 输出 Agent 总结与三套方案（场景种草、细节观察、选购参考），每套明确分为“选题策略—标题 A/B/C—完整笔记”，附标签、配图、依据、验证建议。正文可编辑、复制，完整方案可导出 JSON。
6. 主按钮在本地模式也自动执行 Critic Agent 的 Generate → Evaluate → Refine：三套评分、自检、选择、优化尝试与复评。没有可验证改进时保留原稿并说明，不能伪造“优化成功”。配置模型后勾选“启用 LLM 全流程”，以真实模型完成意图识别、语义标注、结构化生成和 Critic 评估，可自动优化一轮。

本地生成使用规则和框架，并进行本地规则自评；复杂简报可通过 LLM 全流程处理。缺少产品事实时保留待填写内容，避免编造使用经历。没有同类高表现笔记时不给出无关草稿。单条或少量样本、缺少正文会明确提示。

## 连接模型配置

复制 `.env.example` 为 `.env`，填写兼容 Chat Completions 格式的服务：

```dotenv
AI_BASE_URL=https://your-provider.example/v1
AI_API_KEY=your-key
AI_MODEL=your-model
```

应用向根地址追加 `/chat/completions`。密钥在后端读取，不进入浏览器；`.env` 已被 Git 忽略。也可使用同名环境变量。模型支持 HTTPS，localhost/127.0.0.1 本地服务支持 HTTP。

模型未配置时，所有本地分析和模板生成可使用；AI 按钮禁用，不伪装成模型输出。填写后在模型设置中刷新配置状态，再运行具体任务验证连接。AI 输出显示为文本，避免执行源数据或模型返回的 HTML；输出证据仍需人工复核。

只有点击 AI 按钮才发送页面说明的笔记字段和创作简报，最多 12 篇，每篇正文最多 8000 字符；不发送作者、密钥到前端或本地文件路径。当前请求为同步调用，超时约 90 秒；没有服务端取消和跨重启持久化。未实际配置真实模型前，不能将接口实现视为真实服务联调成功。

上传的数据和报告保留在当前页面内存，刷新恢复参考文件；创作简报仅保留在浏览器当前会话。需要保存结果时使用导出。此服务只监听本机地址，供个人研究使用。

## 自我评估与优化

质量分与 ViralScore 完全独立。量表：需求匹配 25、事实可靠 25、结构清晰 20、表达自然 15、原创差异 15。分数来自本地规则或 LLM 评估，页面明确区分；不代表事实已核实或流量预测。选择最佳时优先未解决阻碍项更少的方案，再比较总分。

每轮优化保留原稿、候选稿、前后评分、修改原因和采用状态。候选不得新增阻碍项或降低评分，否则回退原稿；一轮调用有界，不做无限迭代。没有产品事实时，不能通过移除全部事实占位符伪装完成。用户编辑正文后，原评分与最终稿立即失效，需重新评估。

本地优化只能处理显式主题与夸大表达等可检测问题；不能模拟理解全部语义。LLM 可结合用户事实和自由文本要求改写，仍需人工核实最终稿。主按钮勾选 LLM 是一次完整工作流的模型调用授权，页面展示数据范围；多步骤可能耗时数分钟。

## 语义规律与 Lift

“规律洞察”保留词典对照，同时新增 LLM 语义分析。选择最多 40 / 100 篇分层子样本，或当前全部可评分笔记，每批 8 篇。分层按高表现比例分配，在组内按 ID 等距抽取，属于可复现的描述性子样本，不视为随机抽样的显著性证据。

模型看不到分数与高表现标签，只判断情绪共鸣、具体场景、选择价值、细节证据、自然互动、夸大承诺六种语义。每个特征可为 true/false/null；true 必须附精确原文，后端逐条核对，证据无效则该批失败。null 不计入该特征的分母。

Lift = P(高表现 | 特征出现) / P(高表现)。例如高表现组 60/100、其余组 40/400，Lift=(60/100)/(100/500)=3。大于 1 为正关联，小于 1 为负关联；基线、对照或特征出现数不足以计算时显示不可用，不制造无穷值。并展示两组比例差与计数。正负关联仅为描述，不能解读成因果或统计显著。

模型批次失败或用户停止后，已完成结果保留并标为部分分析；不会补成“全量结果”。停止在当前请求完成后生效。结果可随总报告导出。

`tests/test_agents.py` 验证语义证据校验、盲标输入、Lift、评分量表边界、优化回退和引用校验；`tests/test_scoring_v2.py` 验证五维权重、归一化、缺失粉丝及零分母。`tests/agents_browser.cjs` 使用模拟模型响应验证前端全流程、编辑失效和批次失败；这不代表真实模型服务已经联调成功。

## 笔记解析与内容鉴赏
侧栏「笔记解析与内容鉴赏」支持单张 JPG/PNG/WebP（10 MB 内）。系统先划分作者、标题、正文、标签、点赞、收藏、评论和内容图片 8 个区域，再分别使用本机 Windows 中文 OCR；图片不会发送到模型服务。需要 Windows 中文 OCR 语言包和 Pillow；不可用时可手动填写。临时解码图片在识别结束后删除。

识别后所有字段均可修正，修改项会标记为「用户已修正」，鉴赏和评分只读取当前表单值。中文错字、裁切和布局差异仍可能造成识别遗漏。编辑日期、手机状态栏时间、图片内日期和缺少年份的日期都不自动当作发布日期，粉丝数也不猜测。

内容鉴赏不需要粉丝数和发布日期，分别评价标题吸引力、收藏倾向、视觉表达、场景感、产品卖点和互动引导。点赞、收藏、评论齐全时再展示基础数据表现评分；粉丝数和完整发布日期是可选增强字段，补充后增加账号体量修正与互动速度，并形成完整 ViralScore。评分使用当前筛选样本作为固定参照，评分过程不会自动改动样本库；模拟样本参照分不代表真实平台爆款判定。

完成鉴赏后可把核对后的字段一键加入「截图研究库」，或直接带着截图标题进入选题工作台。研究库最多在浏览器本地保存 200 条文本记录，不保存原截图；字段不完整的记录可以参与内容检索，但不会被标记为完整 ViralScore 爆款证据。

## 可解释评分、品类对照与 Critic

笔记详情页展示五个维度的原始定义、样本内百分位、实际贡献和维度满分，并根据最高百分位维度生成「主要优势」。贡献值受权重上限约束，例如互动速度权重为 15% 时贡献不会超过 15 分。

规律洞察可切换全部、创意餐盘、杯碗茶具、托盘与收纳、餐桌布艺、桌面摆件和厨房小物。切换后会在该品类内部重新计算 ViralScore、前 20% 高表现组、Lift 和正负关联。选题生成也先识别或采用指定品类，再在同品类范围重新评分和提取证据。

选题工作台按「需求、证据、方案、评估与成稿」四步显示。Critic 使用需求匹配、标题吸引力、事实完整度、结构清晰度、原创度和参考过度相似风险六维量表，并说明最佳方案胜出原因；优化记录同时保留分数变化、具体修改项和前后正文。
